# CRM 产品文档

## 1. 产品定位

面向尚未使用 CRM 的小型通用 B2B 销售团队，以客户为唯一业务主体，帮助团队持续回答：客户是谁、处于什么生命周期、谁负责、下一步做什么、离回款还有多远。

## 2. 目标用户

系统管理员维护人员、角色和枚举；销售主管管理部门客户、客户公海与漏斗；销售人员处理本人负责或可领取的客户及销售对象；售后人员在 P1 处理已授权客户的工单。

## 3. 核心业务闭环

客户实体 → 生命周期判断与跟进 → 联系人与商机 → 报价单 → 合同 → 回款。客户在待处理、跟进中、已合格和已无效之间流转；商机按实际交易需要在客户下创建。电话、会议、邮件、拜访、任务和备注以活动形式关联客户、联系人、商机、报价或合同。

## 4. 模块划分

### 4.1 客户管理

客户沉淀从潜在到合作的完整主体档案和生命周期，联系人沉淀客户侧人员；客户公海统一展示无负责人的客户并提供领取和分配。

### 4.2 销售管理

商机管理销售预测，产品与报价支持商业方案，合同与回款记录签约和现金事实；拜访是活动类型，工单为 P1 售后闭环。

## 5. 核心对象关系

| 对象 | 唯一职责 | 关键关系 |
| --- | --- | --- |
| 客户 | 唯一的潜在与合作主体，承载生命周期和归属 | 可关联多个联系人、商机、报价、合同、回款和工单；无负责人时进入客户公海 |
| 商机 | 记录可预期交易、阶段、金额和下一步 | 可关联多个报价，最终关联合同 |
| 合同 | 记录最终签约与履约事实 | 可拆分多个回款计划和回款记录 |
| 活动 | 记录销售行动 | 关联客户、联系人、商机、报价或合同 |

客户档案状态、客户生命周期与负责人/公海归属相互独立：`status` 为正常或停用，`lifecycleStatus` 为待处理、跟进中、已合格或已无效，负责人为空且有入池时间时处于客户公海。来源、行业、阶段、原因、单位和回款方式等枚举由设置维护，业务页面仅展示名称。关键归属、生命周期、金额和日期变更必须可追溯。

## 6. 通用交互与反馈规范

### 6.1 列表、抽屉与页签

列表首次加载、搜索、分页和排序时显示加载态；请求失败保留筛选条件并提供“重试”。无数据时区分“尚无数据”（有创建权时显示主操作）与“筛选无结果”（显示清空筛选）；无创建权时不展示越权入口。点击主字段链接或“查看”在右侧打开详情抽屉；关闭抽屉后保留列表筛选、分页和滚动位置。抽屉内保存成功后刷新当前资料与受影响的页签数量，不自动关闭抽屉。

### 6.2 表单与字段反馈

字段校验在失焦或提交时于字段下方显示人类可读提示；服务端校验、权限变化或版本冲突在表单顶部说明原因与恢复方式，已填写内容不丢失。重复候选以可点击记录列表提示但不阻断；用户选择继续时，系统在时间线记录已确认提示。枚举仅显示名称；已停用、不可见或不满足前置条件的关联记录不可选择，并在选择器空态中说明原因。

### 6.3 高风险操作与审计

领取、分配、退回公海、停用、删除、作废、赢单、丢单、关闭和冲销必须先显示确认弹窗，写明对象、影响、必填原因和确认按钮文案。成功提示包含对象名称与结果；失败提示给出下一步。并发领取时提示“该客户刚被其他人领取，请刷新列表”，不静默覆盖。关键字段、状态、归属、金额和日期变更均在时间线记录操作者、时间、变更前后值和原因；无关联对象访问权时仅显示“无访问权限”，不泄露对象名称或敏感字段。

### 6.4 统一验收口径

每个对象文档的验收须至少覆盖：有权限的正常路径、无权限或不可用前置条件、字段校验或关联约束、并发/状态冲突后的恢复。除非对象文档另行规定，删除采用软删除或作废并保留审计记录。

### 6.5 统一 UX 组件约定

业务列表使用 `PageContainer + ProTable`：标题区左侧为名称与计数，右侧为主操作；搜索区默认仅展示高频条件，更多条件收纳到展开区；工具栏按“主操作—常用工具—列设置”排序。新建与编辑使用 `ModalForm`，普通资料宽 640、轻量对象宽 560，危险操作使用 `Modal`，单一且可逆的轻操作使用 `Popconfirm`，更多操作收纳在 `Dropdown`。详情统一使用可调整宽度的右侧 `Drawer`；顶部操作栏固定，内容滚动，状态标签在标题旁并列展示。桌面端有时间线的详情采用资料区与时间线的双栏布局，窄屏降为单栏；所有卡片、Tab、表格和表单遵守页面状态与反馈规范。

每份对象文档的 UX 规格按同一阅读顺序描述：先写列表与工具栏，再写详情抽屉与信息分区，然后写 Tabs/明细、表单与关键动作，最后写加载、空态、失败和不可用状态。详情资料区统一使用 `Card + Descriptions`，关联区统一使用 `Tabs + 紧凑 ProTable`，审计统一使用 `Timeline`；金额统一使用右对齐、千分位和币种前缀，日期统一使用“YYYY-MM-DD HH:mm”。主操作只保留一个 `primary` 按钮，其他操作按风险收纳，避免同一页面出现多个同权重的主按钮。

## 7. MVP 范围

P0 覆盖客户生命周期到回款的可执行闭环、客户公海、活动时间线、轻量数据权限和工作台提醒。评分、自动分配、审批、电子签、财务同步、复杂协同和完整工单流程不进入 P0。

## 8. 后续演进

后续按实际使用数据逐步增加自动化规则、预测模型、审批、电子签、财务集成、客户画像、字段级权限与工单 SLA；不以一次性复杂配置替代小团队的日常执行。
