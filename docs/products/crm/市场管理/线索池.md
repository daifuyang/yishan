# 线索池

## 1. 产品定位

### 1.1 解决什么问题

集中承接无负责人的线索，让销售领取、主管分配，并以池内时长管理滞留风险。

### 1.2 使用角色

销售人员查看和领取；销售主管、管理员可分配；录入人员可新建和导入。

### 1.3 与其他模块的关系

线索池是负责人为空的线索视图，不是独立对象或生命周期状态；领取后回到线索列表。

## 2. 核心业务流程

新建或导入无负责人线索 → 记录入池时间 → 销售领取或主管分配 → 线索移出池内 → 负责人在“线索”中安排下一步。

## 3. 页面设计

### 3.1 列表页

| 区块 | 设计 |
| --- | --- |
| 页面结构 | 页面标题、搜索区、`ProTable`、分页、批量导入和新增线索。 |
| 搜索 | 关键字、线索状态、来源枚举、入池时间范围。 |
| 列 | 联系人、公司、状态、来源、入池时间、池内时长、创建时间、操作。 |
| 操作 | 查看、领取；主管和管理员额外提供分配。 |

不展示下次跟进或逾期提醒。

### 3.2 详情页

| 区块 | 内容 |
| --- | --- |
| 顶部 | 联系人或公司、状态、入池时间、池内时长、领取和分配动作。 |
| 基本资料 | 联系方式、来源枚举、意向说明、创建人。 |
| 历史 | 既有活动、状态和归属变更可查看；不允许在池内写跟进。 |

### 3.3 新建 / 编辑

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| 联系人 | 文本 | 是 | 不能为空。 |
| 公司与联系方式 | 文本 | 否 | 用于重复提示。 |
| 来源 | 枚举下拉 | 否 | 设置维护，展示名称。 |
| 意向说明 | 多行文本 | 否 | 记录初步需求。 |

池内不直接编辑，需先领取。

## 4. 数据模型

### 4.1 核心字段

复用线索资料、状态和来源，增加入池时间；负责人和负责人部门为空是池内识别条件。

### 4.2 状态

保留线索的待处理、跟进中、已合格、已无效，不另设池状态。

### 4.3 关联关系

领取或分配创建负责人关系；退回线索池解除负责人关系并重新记录入池时间。

## 5. 功能需求

### 5.1 查询

支持关键字、状态、来源和入池时间查询，并按池内时长排序。

### 5.2 新增

手工新建和批量导入均创建无负责人线索，并记录入池时间。

### 5.3 编辑

池内不提供资料编辑，避免无负责人的记录被多人并行修改。

### 5.4 状态流转

领取和分配只改变归属；不改变线索资格状态。无负责人线索没有下一步计划。

### 5.5 删除 / 作废

删除为软删除；无效由线索资格操作处理，不在池内独立处理。

## 6. 权限与数据可见性

### 6.1 查看权限

所有具备线索查看权限的用户可查看池内记录。

### 6.2 操作权限

领取需领取权限；分配需分配权限；新建、导入和删除分别授权。

### 6.3 数据范围

池内记录对可领取用户可见；领取后按负责人数据范围可见。

## 7. 业务规则

池内时长由当前时间减入池时间计算；创建时间不替代入池时间；枚举仅显示名称。

## 8. 异常与边界场景

并发领取只允许一人成功；已转化或无效线索不得领取；导入逐条校验并返回失败行。

## 9. MVP 范围

### 9.1 P0

新建、导入、查询、领取、分配、入池时间和池内时长。

### 9.2 P1

自动回收、自动分配和池内 SLA 规则。

### 9.3 暂不支持

池内写跟进、批量领取和智能推荐。

## 10. 验收标准

无负责人线索可进入池内并显示入池时间和池内时长；领取后移出池内，销售才能安排下一步；池内页面不显示跟进逾期。
