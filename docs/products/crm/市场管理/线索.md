# 线索

## 1. 产品定位

### 1.1 解决什么问题

记录尚未确认价值的潜在客户，帮助销售完成归属、跟进、资格判断和转化。

### 1.2 使用角色

销售人员处理本人线索；销售主管处理本部门线索并分配；管理员处理全部线索。

### 1.3 与其他模块的关系

线索可进入线索池；合格后创建或关联客户、联系人，并可按交易需要创建商机。

## 2. 核心业务流程

录入线索 → 分配负责人或进入线索池 → 记录活动与下一步 → 判定合格或无效 → 合格线索转化为客户、联系人和可选商机。

## 3. 页面设计

### 3.1 列表页

| 区块 | 设计 |
| --- | --- |
| 页面结构 | 页面标题、搜索区、`ProTable`、分页、右上角新增线索。 |
| 搜索 | 关键字、状态、负责人、来源枚举、创建时间范围。 |
| 列 | 联系人、公司、状态、负责人、下一步、来源、创建时间、操作。 |
| 操作 | 查看、编辑、写跟进、转移、退回线索池、合格、无效、转化。 |

空值显示 `—`；下一步逾期只在负责人存在时标记。

### 3.2 详情页

| 区块 | 内容 |
| --- | --- |
| 顶部 | 联系人或公司、资格状态、负责人、关键动作。 |
| 基本资料 | 联系人、公司、联系方式、来源枚举、意向说明。 |
| 资格判断 | 状态、资格证据、无效原因、转化信息。 |
| 关联对象 | 客户、联系人、商机。 |
| 右侧时间线 | 活动、负责人变更、状态变更和转化记录；可写跟进。 |

### 3.3 新建 / 编辑

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| 联系人 | 文本 | 是 | 去除首尾空格后不能为空。 |
| 公司、手机、电话、邮箱、微信 | 文本 | 否 | 手机、电话、邮箱用于重复提示。 |
| 来源 | 枚举下拉 | 否 | 选项由设置维护，仅回显名称。 |
| 意向说明 | 多行文本 | 否 | 记录初步需求。 |

## 4. 数据模型

### 4.1 核心字段

联系人、公司、联系方式、来源、意向说明、负责人、负责人部门、创建人、下一步、资格证据、无效原因、转化关联和时间戳。

### 4.2 状态

待处理、跟进中、已合格、已无效。是否在池内和是否已转化不属于状态。

### 4.3 关联关系

一条线索可关联多条活动、一个负责人、一个来源枚举项，以及转化后的客户、联系人和可选商机。

## 5. 功能需求

### 5.1 查询

支持关键字、状态、负责人、来源和创建时间筛选，按下一步和更新时间辅助排序。

### 5.2 新增

默认由创建人负责；允许管理员或主管在新建后分配，也可直接进入线索池。

### 5.3 编辑

普通资料可编辑；归属、资格状态和转化关系通过独立动作维护。

### 5.4 状态流转

跟进后进入跟进中；满足资格标准时填写证据后标记已合格；无效必须选择原因并填写说明。

### 5.5 删除 / 作废

删除为软删除；已转化线索不可删除。无效线索保留历史，可在授权后重新激活。

## 6. 权限与数据可见性

### 6.1 查看权限

管理员查看全部；主管查看本人及本部门；销售查看本人和可领取池内线索。

### 6.2 操作权限

查看、创建、编辑、删除、领取、分配、资格判断和转化分别授权。

### 6.3 数据范围

按负责人和负责人部门过滤；无负责人记录按线索池规则可见。

## 7. 业务规则

创建时提示公司名称、手机、电话和邮箱的重复候选；合格转化不强制创建商机；已转化线索不可重复转化。

## 8. 异常与边界场景

无负责人线索不产生下一步逾期；并发领取仅允许一人成功；无效线索不能直接转化；无权限对象按不可见处理。

## 9. MVP 范围

### 9.1 P0

录入、导入、分配、活动、资格判断、转化、重复提示和时间线。

### 9.2 P1

评分、自动分配、自动回收和批量培育。

### 9.3 暂不支持

AI 线索评分与自动化营销触达。

## 10. 验收标准

销售可将线索录入、跟进、判定合格或无效；合格线索可创建或关联客户、联系人和商机；所有关键变化可在详情时间线追溯。
