# 联系人

## 1. 产品定位

### 1.1 解决什么问题

记录客户侧人员、联系信息和决策角色，帮助销售识别正确的沟通对象。

### 1.2 使用角色

销售人员维护可见客户的联系人；主管和管理员维护部门或全部范围。

### 1.3 与其他模块的关系

联系人必须归属客户，可关联线索转化记录、商机、活动、报价和合同。

## 2. 核心业务流程

创建或由线索转化联系人 → 维护职位和决策角色 → 关联商机与活动 → 随客户关系持续更新。

## 3. 页面设计

### 3.1 列表页

| 区块 | 设计 |
| --- | --- |
| 搜索 | 关键字、客户、决策角色、负责人、创建时间。 |
| 列 | 姓名、客户、部门、职位、决策角色、手机、邮箱、负责人、创建时间、操作。 |
| 操作 | 查看、编辑、设为关键联系人、删除。 |

### 3.2 详情页

| 区块 | 内容 |
| --- | --- |
| 顶部 | 姓名、客户、职位、关键联系人标记和操作。 |
| 基本资料 | 部门、职位、决策角色、联系方式、说明。 |
| 关联 | 相关商机、报价、合同和活动时间线。 |

### 3.3 新建 / 编辑

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| 客户 | 客户选择 | 是 | 必须选择可见且正常的客户。 |
| 姓名 | 文本 | 是 | 不能为空。 |
| 部门、职位 | 文本 | 否 | 描述组织位置。 |
| 决策角色 | 枚举下拉 | 否 | 例如决策者、影响者、使用者、采购者。 |
| 手机、电话、邮箱、微信 | 文本 | 否 | 用于重复提示和联系。 |

## 4. 数据模型

### 4.1 核心字段

客户、姓名、部门、职位、决策角色、联系方式、关键联系人标记、说明和创建信息。

### 4.2 状态

联系人不使用独立生命周期状态；是否为关键联系人为属性。

### 4.3 关联关系

一个联系人属于一个客户，可关联多个商机、活动、报价和合同。

## 5. 功能需求

### 5.1 查询

支持关键字、客户、决策角色、负责人和创建时间查询。

### 5.2 新增

支持客户详情内新增、全局新增和线索转化；提示手机、电话、邮箱重复。

### 5.3 编辑

可维护基本资料和决策角色；更换客户需同步检查关联经营对象。

### 5.4 状态流转

不适用；关键联系人可设定或取消。

### 5.5 删除 / 作废

无关联经营事实时可软删除；有报价、合同或活动记录时仅允许停用联系信息。

## 6. 权限与数据可见性

### 6.1 查看权限

联系人继承所属客户的数据可见性。

### 6.2 操作权限

联系人查看、创建、编辑、删除和客户归属变更分别授权。

### 6.3 数据范围

客户负责人、部门和公海规则决定联系人可见性。

## 7. 业务规则

联系人必须有客户归属；决策角色由设置维护；联系方式重复只提示不阻断。

## 8. 异常与边界场景

停用客户不可新增联系人；变更客户时，关联商机或合同不自动迁移；无权限客户不可选择。

## 9. MVP 范围

### 9.1 P0

联系人档案、决策角色、关键联系人、活动关联和重复提示。

### 9.2 P1

决策链、影响力图谱和联系人偏好。

### 9.3 暂不支持

跨客户联系人和自动关系识别。

## 10. 验收标准

销售可在客户下维护联系人、标记决策角色并查看关联活动；联系人可见性与客户保持一致。
