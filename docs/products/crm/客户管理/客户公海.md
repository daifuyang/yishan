# 客户公海

## 1. 产品定位

### 1.1 解决什么问题

集中管理无负责人的客户，使团队能重新领取或分配已识别但暂未跟进的合作主体。

### 1.2 使用角色

销售人员领取；主管和管理员分配、回收和查看池内时效。

### 1.3 与其他模块的关系

客户公海是负责人为空的客户视图，不是客户状态；领取后返回客户列表。

## 2. 核心业务流程

创建未分配客户或退回公海 → 记录入池时间 → 领取或分配 → 客户进入负责人范围 → 在客户或商机中安排下一步。

## 3. 页面设计

### 3.1 列表页

| 区块 | 设计 |
| --- | --- |
| 搜索 | 关键字、客户级别、行业、来源枚举、入池时间范围。 |
| 列 | 客户名称、级别、行业、来源、入池时间、池内时长、创建时间、操作。 |
| 操作 | 查看、领取；主管和管理员可分配。 |

不展示下次跟进和逾期提醒。

### 3.2 详情页

| 区块 | 内容 |
| --- | --- |
| 顶部 | 客户名称、入池时间、池内时长、领取和分配。 |
| 资料 | 客户基础资料、联系人摘要、历史商机和合同摘要。 |
| 时间线 | 查看历史活动和归属变更；池内不允许写跟进。 |

### 3.3 新建 / 编辑

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| 客户名称 | 文本 | 是 | 不能为空并提示重复。 |
| 类型、级别、行业、来源 | 枚举下拉 | 否 | 设置维护。 |
| 联系方式与说明 | 文本、多行文本 | 否 | 用于识别和补充背景。 |

池内需领取后才可编辑。

## 4. 数据模型

### 4.1 核心字段

复用客户资料，负责人为空并记录入池时间；池内时长由当前时间计算。

### 4.2 状态

保留客户正常、停用状态，不另设公海状态。

### 4.3 关联关系

领取或分配建立客户负责人关系；退回公海解除负责人关系并重新记录入池时间。

## 5. 功能需求

### 5.1 查询

支持关键字、级别、行业、来源和入池时间筛选，支持按池内时长排序。

### 5.2 新增

允许直接创建无负责人客户，系统记录入池时间。

### 5.3 编辑

池内不直接编辑，领取后在客户页维护。

### 5.4 状态流转

领取、分配和退回只改变归属，不改变客户正常或停用状态。

### 5.5 删除 / 作废

遵循客户删除和停用规则；存在经营事实的客户不能直接删除。

## 6. 权限与数据可见性

### 6.1 查看权限

具备客户查看权限的用户可查看可领取公海客户。

### 6.2 操作权限

领取、分配、退回、删除和停用分别授权。

### 6.3 数据范围

领取后按负责人和部门进入数据范围；池内时按公海规则开放。

## 7. 业务规则

创建时间不替代入池时间；池内时效用于运营分配，不作为销售跟进逾期。

## 8. 异常与边界场景

并发领取只允许一人成功；停用客户不可领取；有未结经营事项的客户退回公海需主管权限。

## 9. MVP 范围

### 9.1 P0

查询、领取、分配、退回、入池时间和池内时长。

### 9.2 P1

保护期、自动释放、自动回收和分配策略。

### 9.3 暂不支持

池内写跟进、批量领取和智能推荐。

## 10. 验收标准

无负责人客户显示入池时间与池内时长；领取后移出公海；公海页面不显示下一步和逾期提醒。
