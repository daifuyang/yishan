# 客户公海

## 1. 产品定位

### 1.1 解决什么问题

集中管理无负责人的客户，使团队能重新领取或分配已识别但暂未跟进的合作主体。

### 1.2 使用角色

销售人员领取；主管和管理员分配、回收和查看池内时效。

### 1.3 与其他模块的关系

客户公海是负责人为空的客户视图，不是客户状态；领取后返回客户列表。

## 2. 核心业务流程

创建未分配客户或退回公海 → 记录入池时间 → 领取或分配 → 客户进入负责人范围 → 在客户或商机中安排下一步。

## 3. 页面设计

### 3.1 列表页

页面使用 `PageContainer` 承载 `ProTable`，以客户 ID 为行标识。仅查询负责人为空的客户，默认按入池时间正序展示；工具栏提供刷新、密度和列设置，主操作为“领取客户”。

| 区块 | 布局 / 组件 | 展示内容或行为 |
| --- | --- | --- |
| 页面标题 | `PageContainer` | 显示“客户公海”，并展示当前筛选结果数量。 |
| 搜索区 | `ProTable` 内置搜索表单 | 默认显示关键字、级别和行业；可展开来源、入池时间。 |
| 工具栏 | 表格工具栏 | 刷新、密度和列设置；不提供新建客户入口。 |
| 数据表格 | `ProTable` | 客户名称可打开详情；支持分页和横向滚动。 |
| 分页 | 内置分页 | 支持切换每页条数和翻页。 |

搜索字段配置如下。

| 搜索标签 | 字段名 | 控件类型 | 选项 / 行为 |
| --- | --- | --- | --- |
| 关键字 | `keyword` | 文本输入框 | 匹配客户名称、电话和邮箱。 |
| 客户级别 | `levelId` | 下拉选择 | 读取设置中启用的客户级别。 |
| 行业 | `industryId` | 下拉选择 | 读取设置中启用的行业。 |
| 客户来源 | `sourceId` | 下拉选择 | 读取设置中启用的来源枚举。 |
| 入池时间 | `poolEnteredAtRange` | 日期范围选择器 | 按进入公海的时间筛选。 |

表格列配置如下。

| 列标题 | 字段名 | 展示类型 | 宽度 | 展示规则 | 是否参与搜索 |
| --- | --- | --- | --- | --- | --- |
| 客户名称 | `name` | 文本链接 | 240 | 点击打开详情；空值显示 `—`。 | 是 |
| 客户级别 | `levelName` | 枚举标签 | 96 | 回显配置名称。 | 是 |
| 行业 | `industryName` | 文本 | 120 | 回显配置名称。 | 是 |
| 客户来源 | `sourceName` | 文本 | 120 | 只显示具体枚举名称。 | 是 |
| 入池时间 | `poolEnteredAt` | 日期时间 | 168 | 入池时写入，不用创建时间替代。 | 是 |
| 池内时长 | `poolDuration` | 时长文本 | 104 | 由当前时间减入池时间计算；不属于客户字段。 | 否 |
| 创建时间 | `createdAt` | 日期时间 | 168 | 使用日期时间格式。 | 否 |
| 操作 | `option` | 操作链接 | 128 | 查看、领取；主管和管理员额外显示分配。 | 否 |

不展示下次跟进和逾期提醒。

### 3.2 详情页

详情使用右侧抽屉。主信息在左侧呈现，右侧保留历史活动与归属变更时间线；池内页面不提供写跟进入口。

| 区块 | 布局 / 组件 | 展示内容或行为 |
| --- | --- | --- |
| 标题区 | 抽屉标题 | 客户名称、入池时间、池内时长；右侧显示领取或分配。 |
| 基本资料 | 两列信息网格 | 类型、级别、行业、来源、电话、邮箱、地址、官网和说明。 |
| 关联摘要 | `Tabs` | 联系人、商机、报价、合同、回款，均为只读摘要。 |
| 右侧动态 | 活动时间线 | 展示历史沟通、归属变更和入池记录，支持类型和时间筛选。 |
| 操作区 | 按钮组 | 销售显示领取；主管与管理员显示分配和编辑。 |

### 3.3 新建 / 编辑

客户公海不单独提供新建表单。新建客户时未指定负责人，或已分配客户执行“退回客户公海”后，记录进入本页面；编辑复用客户资料表单。

| 字段 | 字段名 | 组件类型 | 操作 | 校验 / 展示规则 |
| --- | --- | --- | --- | --- |
| 负责人 | `ownerUserId` | 人员选择器 | 领取 / 分配 | 领取时固定为当前用户；分配时选择有客户访问权限的人员。 |
| 入池时间 | `poolEnteredAt` | 系统写入 | 退回公海 | 用户不可编辑；每次重新入池时刷新。 |
| 退回原因 | `poolReturnReason` | 多行文本框 | 退回公海 | 可选；最多 1000 字，写入归属变更记录。 |

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| 客户名称 | 文本 | 是 | 不能为空并提示重复。 |
| 类型、级别、行业、来源 | 枚举下拉 | 否 | 设置维护。 |
| 联系方式与说明 | 文本、多行文本 | 否 | 用于识别和补充背景。 |

池内需领取后才可编辑。

## 4. 数据模型

### 4.1 核心字段

复用客户资料，负责人为空并记录入池时间；池内时长由当前时间计算。

### 4.2 状态

保留客户正常、停用状态，不另设公海状态。

### 4.3 关联关系

领取或分配建立客户负责人关系；退回公海解除负责人关系并重新记录入池时间。

## 5. 功能需求

### 5.1 查询

支持关键字、级别、行业、来源和入池时间筛选，支持按池内时长排序。

### 5.2 新增

允许直接创建无负责人客户，系统记录入池时间。

### 5.3 编辑

池内不直接编辑，领取后在客户页维护。

### 5.4 状态流转

领取、分配和退回只改变归属，不改变客户正常或停用状态。

### 5.5 删除 / 作废

遵循客户删除和停用规则；存在经营事实的客户不能直接删除。

## 6. 权限与数据可见性

### 6.1 查看权限

具备客户查看权限的用户可查看可领取公海客户。

### 6.2 操作权限

领取、分配、退回、删除和停用分别授权。

### 6.3 数据范围

领取后按负责人和部门进入数据范围；池内时按公海规则开放。

## 7. 业务规则

创建时间不替代入池时间；池内时效用于运营分配，不作为销售跟进逾期。

## 8. 异常与边界场景

并发领取只允许一人成功；停用客户不可领取；有未结经营事项的客户退回公海需主管权限。

## 9. MVP 范围

### 9.1 P0

查询、领取、分配、退回、入池时间和池内时长。

### 9.2 P1

保护期、自动释放、自动回收和分配策略。

### 9.3 暂不支持

池内写跟进、批量领取和智能推荐。

## 10. 验收标准

无负责人客户显示入池时间与池内时长；领取后移出公海；公海页面不显示下一步和逾期提醒。
