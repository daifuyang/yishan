# 客户

## 1. 产品定位

### 1.1 解决什么问题

沉淀已识别的合作主体，集中呈现联系人、商机、报价、合同、回款和活动。

### 1.2 使用角色

销售人员维护本人客户；主管管理部门客户；管理员维护全部客户与归属。

### 1.3 与其他模块的关系

客户来自线索转化或直接新建，是联系人、商机、合同、回款和工单的共同主体。

## 2. 核心业务流程

创建或转化客户 → 指定负责人 → 建立联系人 → 创建商机 → 关联报价、合同和回款 → 持续记录活动。

## 3. 页面设计

### 3.2 详情页

| 区块 | 内容 |
| --- | --- |
| 顶部 | 客户名称、状态、负责人和编辑、转移等关键动作。 |

### 3.3 新建 / 编辑

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| 客户名称 | 文本 | 是 | 用于公司名称重复提示。 |
| 客户类型、级别、行业、来源 | 枚举下拉 | 否 | 由设置维护，回显名称。 |

| 说明 | 多行文本 | 否 | 记录合作背景。 |

## 4. 数据模型

### 4.1 核心字段

名称、类型、级别、行业、来源、联系方式、地址、负责人、负责人部门、状态、入池时间和说明。

### 4.2 状态

正常、停用。公海归属不属于客户状态。

### 4.3 关联关系

一个客户可关联多个联系人、商机、报价、合同、回款、活动和 P1 工单。

## 5. 功能需求

### 5.1 查询

支持关键字、状态、负责人、级别、行业、来源和时间范围筛选。

### 5.2 新增

支持直接新建与线索转化；创建时提示同名客户和重复联系方式。

### 5.3 编辑

可维护资料、负责人和状态；停用客户保留历史关联，不可新增商机和报价。

### 5.4 状态流转

正常客户可停用；停用后可在授权下恢复正常。退回公海只改变负责人和入池时间。

### 5.5 删除 / 作废

无关联商机、合同和回款时可软删除；存在经营事实时仅允许停用。

## 6. 权限与数据可见性

### 6.1 查看权限

管理员查看全部；主管查看本人和本部门；销售查看本人及可领取公海客户。

### 6.2 操作权限

客户查看、创建、编辑、删除、领取、转移和停用分别授权。

### 6.3 数据范围

按负责人和部门过滤；客户公海按领取规则开放。

## 7. 业务规则

客户不是交易阶段；商机才承载预计金额和成交进度。来源、级别和行业为设置枚举，只展示名称。

## 8. 异常与边界场景

重复候选只提示不阻断；已停用客户不允许新增销售对象；有合同或回款的客户不能直接删除。

## 9. MVP 范围

### 9.1 P0

客户档案、负责人、公海、联系人、关联经营对象、活动时间线和重复提示。

### 9.2 P1

协同人、保护期、客户画像和自动释放。

### 9.3 暂不支持

字段级脱敏、自定义对象和自动客户评分。

## 10. 验收标准

用户可创建或转化客户，查看其联系人与销售链路；归属变更和停用可追溯；客户与交易进度保持分离。
