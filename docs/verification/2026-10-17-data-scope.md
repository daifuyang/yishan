# DataScope 剩余问题修复与验证

## 修复

- 默认 AuthProvider 在已验证令牌后显式免过滤读取身份，避免认证前没有范围上下文而误判用户不存在。
- UserDirectory 单条查询与批量查询统一为内部身份解析；业务用户查询仍由受限 Service 执行。真实 MySQL 验证 seed actor 可正常解析。
- 修复 Drizzle 关联查询把部门子查询列映射成外层用户别名的问题。子查询使用独立 SQL 标识符，用户主键仍可映射到外层别名。
- 移动通讯录部门成员查询、仪表盘在线人数统计接入范围条件。受限及缺少上下文的仪表盘请求不读写全局统计缓存，缓存键升级以避开旧数据。
- 修正 AI 工具描述和代码注释，明确角色、部门等配置按功能权限访问，不再声称已具备行级限制。
- 从真实启动的产品实例取得 OpenAPI，对齐角色 deptIds 描述并重新生成客户端；产品集成测试持续比较运行时与文件契约。

## 适用边界

用户、登录日志及其统计、通讯录用户应用数据范围。角色、部门、岗位、菜单、字典、枚举和附件保留现有功能权限模式，不新增未经定义的归属维度。内部部门树读取与业务部门接口是独立路径，内部免过滤不是业务接口必须放开的理由。

本次没有浏览器验证角色表单，也没有调用外部模型；AI 数据范围由执行链测试覆盖，不代表完成真实模型端到端验收。
