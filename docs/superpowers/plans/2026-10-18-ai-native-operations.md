# AI Native 业务辅助实现计划

依据：用户提供的《Yishan AI Native 企业后台架构审查与实现规范》（2026-10-18）。

目标：在 `dev @ 83b995de` 的现有实现上接通动态发现、持久草稿和原生表单；正式写入继续由用户点击原有表单提交。工作开始时工作区干净。

## 现状与边界

保留 AI SDK 单运行时、会话与租约、现有作用域能力目录、RBAC/PAT/数据范围执行链、ActionDraftService/Repository、原生业务表单及提交参与者。当前缺口是默认内存预填绕过草稿、模块声明未装配、用户业务硬编码在 Runtime、部门未完整适配。

不新增业务 Agent、权限表、通用 HTTP/SQL 工具、动态代码渲染或数据库表。不迁移现有模块目录。敏感字段只留在原生控件。现有接口保持兼容。

## 实现任务

1. 能力目录与草稿：接通 module.capabilities；发现阶段过滤安装/启用/权限；为现有能力增加操作与表单语义；通用工具门面复用原 execute；用户创建与部门创建复用持久 CAS 草稿及原业务提交。先增加参数、安全、状态机和第二表单回归测试。
2. 运行时：仅暴露 discover_operations、describe_operation、query_business_data、update_form_draft，按需读取 Schema；删除用户专属提示和步骤；保留廉价只读规则；真正限制工具调用数；裁剪模型历史而保留完整持久消息；记录无敏感内容的成本/状态指标。先测试多调用预算、上下文边界和流式状态。
3. 原生表单联动：复用现有 Bridge、版本与来源记录；人工修改不得静默覆盖；当前轮工具结果立即应用且去重；会话切换解绑和恢复；用户与部门接入同一协议及表单 AI 入口；提交只由现有按钮触发。先测试人工冲突、旧结果、切换与恢复。
4. 集成：生成 OpenAPI 和客户端，核实 public exports；执行用户和部门的真实浏览器流程；更新接入规范与架构评估。测试不得绕过权限或自动创建正式业务数据。

## 共享接口与并行边界

| 任务 | 产物与消费者 | 约束 |
| --- | --- | --- |
| 1 → 2 | `createOperationTools(execution): AiExecutionEnv` | 固定四工具；内部仍走原授权执行链 |
| 1 → 3 | 既有 action.draft/API 扩展 department.create | 保留 user.create 与旧会话兼容；Schema 同源 |
| 2 → 3 | 标准 SDK UI tool output stream | 完成结果可即时处理；历史不可重放 |
| 1、2、3 → 4 | 实际实现和聚焦测试 | 不通过削弱检查解决失败 |

审查裁决：最新规范明确要求结构化持久草稿，覆盖早期仅内存预填约定；复用已有草稿引擎，不能再增加另一套状态。用户已要求按最小方案直接实施，无需另等架构选择。跨租户能力按实际模型报告，不虚构现有系统没有的租户隔离。

## 验收

先运行新增及相关聚焦测试，再运行 `pnpm check:boundaries`、`pnpm check:openapi`、`pnpm typecheck:api`、`pnpm typecheck:admin`。相关 API、Admin 测试及生产构建按变更范围执行。浏览器验证自然语言→发现→真实选项→草稿→原表单，人工修改保护、多轮与会话恢复、无确认不写入；部门验证相同链路。所有未验证或不支持项在交付报告中明示。
