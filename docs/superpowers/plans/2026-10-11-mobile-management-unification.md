# App 管理页面第一批统一实施计划

**目标：** 按用户、角色管理的现有规范统一岗位、部门、字典的已实现功能。

**设计依据：** 当前会话已确认的列表、详情、独立表单、底部操作和底部筛选面板规范。

**组织：** 在当前工作区并行处理独立业务目录，主智能体负责共享导航与最终验收。保留当前会话修改和其他未提交工作，不提交、不推送。

## 统一约束

- 使用现有 Management、Detail、Form 组件，白色搜索区与底部状态筛选。
- 列表点击进入详情，详情展示业务信息与折叠记录，底部编辑/更多操作；新建、编辑用独立页面。
- 仅使用现有接口及字段；保留权限、账号隔离、异步请求有效性、禁止重复提交、失败保留输入。
- 保留部门层级导航、成员与子部门，保留字典类型与字典项关系。
- 不虚构排序或筛选能力，不改 API，不新增依赖。

## 实施任务

- [x] 岗位：列表、详情、独立新建/编辑表单；维护岗位相关测试。
- [x] 部门：层级列表、详情、独立表单；维护部门相关测试。
- [x] 字典：类型/字典项列表、详情、独立表单；维护字典相关测试。
- [x] 集成：登记 routes、page-config、registry 的新增页面；记录通用设计规范与后续清单。
- [x] 验收：聚焦行为测试、移动端类型检查、App 测试、小程序构建、H5 浏览器检查、边界检查。

## 后续清单

第二批：系统与个人登录日志、只读地区、模块管理、个人资料/改密。

单独设计：通讯录、Web 菜单、工作台配置、媒体库、站点和云存储。

需要真实业务接入：消息中心、首页待办、CRM/商城/门户移动页面。

## 实际验收

263 项 App 测试、移动端类型检查、公共边界检查通过。H5 与小程序构建通过（存在既有体积、浏览器数据和 Taro 缓存警告）。浏览器以隔离接口数据验收 14 个页面在 390px / 320px 下的显示，验证岗位编辑、部门继承父级新建、字典项类型上下文与编辑提交；未做真机验收。
