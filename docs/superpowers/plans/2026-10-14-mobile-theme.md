# 移动端主题基础层实施计划

**目标：** 只升级移动 UI 基础层，保留业务页面源码和业务流程。

**架构：** `@yishan/ui/mobile/theme` 提供两套完整语义色板与可注入主题控制器；CSS 变量保留现有名字，系统媒体查询提供首次绘制默认值。Demo App 管理自己的主题缓存、H5 根节点、小程序 page-meta 和原生导航配色。尺寸与安全区集中在现有 tokens.scss。

**约束：** 不改 API、鉴权、路由、业务表单和页面源码；不增加依赖、不提交构建产物。默认 system；显式 light/dark 优先于系统；持久化失败不能阻断主题切换。基础层只使用语义颜色，色值只允许出现在主题定义中。原生导航和原生 TabBar 已占用的安全区不重复添加。

- [x] 主题控制器：先测试默认模式、手动覆盖、跟随系统、订阅销毁、缓存异常与实例隔离，再实现公开接口 `createThemeController`、`setMode`、`start`、`subscribe`、`getSnapshot`。
- [x] Token：保留旧变量，补齐两套颜色、状态/前景色、阴影、字号语义与 44px 最小触控区域；测试色板键一致、CSS 输出一致与基础层颜色约束。
- [x] App 接入：H5 同步 documentElement，微信通过构建钩子统一注入 page-meta，生命周期钩子同步每个页面及导航；测试页面栈、原始生命周期保留和安全区计算。
- [x] 基础组件：迁移共享 UI、通用 App 组件及确认弹窗；SVG 颜色改为 CSS mask，WeUI 仅替换颜色声明并保留滚轮几何与交互；不改业务页面。
- [x] 验证与交付：移动端类型检查、App/Core 测试、边界与 Taro 检查、weapp/H5 构建及 H5 浏览器验证；写入主题架构、修改文件和页面迁移说明。
