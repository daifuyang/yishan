# App 管理页面第二批实施计划

**目标：** 沿用用户/角色及第一批管理页面规范，完善已有登录日志、地区、模块、个人资料和修改密码。

**依据：** 当前会话已批准的第二批清单。只使用现有 API，不虚构筛选、统计和详情字段，不新增依赖，不提交或推送。

## 任务

- [ ] 系统登录日志：白色搜索区、底部状态/时间筛选、紧凑列表、独立只读详情，保留分页/刷新与账号隔离。
- [ ] 个人登录记录：统一列表与详情（按个人接口能力实现），不引入管理员权限或不存在的服务端筛选。
- [ ] 地区：只读省市区层级导航、搜索路径、清楚的叶子信息，保留全部搜索结果可达，不制造编辑入口。
- [ ] 模块：列表、只读详情及已有启停操作，服务器未开放时清楚提示；操作校验实时权限和账号。
- [ ] 个人资料/改密：统一 Form* 分组和固定保存，保留头像、选择器、密码可见性、校验、失败输入和真实登录失效流程。
- [ ] 集成：统一页面注册、缓存依赖、只读详情数据边界；子智能体审查与修复。
- [ ] 验证：聚焦行为测试、全 App 测试、类型检查、lint、边界、小程序/H5构建、浏览器功能与窄屏验证。

## 约束

列表使用现有 Management*，详情使用 Detail*，表单使用 Form*；状态单选使用 BottomSelectSheet，多条件时间筛选保留草稿并确认生效。H5 页面自定义导航，小程序原生导航（层级浏览页面可保留明确的自定义导航）。保留所有功能、权限、重复提交保护、错误重试及账号切换请求保护。

## 验收边界

浏览器使用隔离接口数据验证交互，不操作线上数据；本轮不具备微信真机环境，不宣称真机通过。第三批的菜单、工作台配置、媒体库、站点、云存储和通讯录不在此次实施范围。
