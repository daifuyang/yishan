# CRM 客户详情商机设计

## 目标

在客户详情 Drawer 中提供可创建、可查看的商机工作区。商机表示一次具体销售机会；客户仍是长期关系主体。创建首个有效商机必须原子地将客户推进到“有商机”并写入客户动态。

## 范围

- 重构客户 Drawer 的商机 Tab 为符合 Ant Design Pro 规范的轻量 `ProTable`。
- 从商机 Tab 空状态、工具栏和客户 Drawer 顶部“新增”复用同一新建商机 Drawer。
- 将商机阶段收敛为 `requirement`、`proposal`、`negotiation`、`won`、`lost`。
- 增加创建表单所需的商机字段、API 校验、事务和活动记录。
- 创建成功后局部刷新客户详情、商机列表和动态，不整页刷新。

不包含商机完整详情页、编辑/赢单/失败操作 UI、报价单关联改造、合同/回款流程或联系人创建流程。

## 数据模型与迁移

`crm_opportunity` 保持客户、负责人、联系人和预计金额的既有字段，并补足以下业务字段：

- `requirement`：客户需求，最长 2000 字符。
- `scope`：采购范围，最长 1000 字符。
- `next_action`：下一步，最长 500 字符。
- `next_follow_up_at`：下次跟进时间。

预计金额继续用 `expected_amount_cents` 以分存储。该值的业务语义是预计成交金额，不与报价、合同和回款金额互相覆盖。

阶段使用唯一的五阶段枚举：

| 内部值 | 中文展示 | 类型 |
| --- | --- | --- |
| `requirement` | 需求确认 | 进行中 |
| `proposal` | 方案报价 | 进行中 |
| `negotiation` | 商务谈判 | 进行中 |
| `won` | 成交 | 终态 |
| `lost` | 失败 | 终态 |

迁移会将现有 `discover` 与 `qualify` 映射为 `requirement`，并更新商机表及阶段日志中的旧值。状态机、请求 schema、响应 schema、前端状态映射和测试只保留新枚举。

## API 与事务

继续使用现有 `POST /api/crm/v1/opportunities`，不创建重复资源。请求新增需求、采购范围、下一步、下次跟进时间；`customerId`、名称、负责人、阶段、预计成交日期、下一步和下次跟进时间为必填。创建时阶段限制为进行中阶段，默认 `requirement`；`won` 与 `lost` 仅能由后续业务动作进入。

服务层将下列步骤置于同一数据库事务：

1. 创建商机并绑定客户、负责人和可选联系人。
2. 写入一条客户维度的 `opportunity_created` 活动，metadata 带商机 ID、名称、金额、预计成交日期和阶段。
3. 重算客户生命周期。
4. 仅当生命周期实际从 `potential` 或 `following` 变为 `opportunity` 时，写入客户维度的 `status_change` 活动。

客户为 `opportunity` 或 `customer` 时，新建商机不得使其倒退；第二条商机不会生成重复状态变更活动。现有活动展示层将 `opportunity_created` 映射为“商机创建”，只显示关键业务信息。

## 客户 Drawer

商机 Tab 使用未嵌套 Card 的 `ProTable`：

- `headerTitle` 显示 `商机（N）`。
- `toolBarRender` 放置带 `Plus` 图标的主按钮“新建商机”。
- 列为商机名称、阶段、预计金额、预计成交、负责人、下一步、操作。
- 名称可点击，名称与“查看”调用同一个 `onOpportunityClick(opportunityId)` 预留入口。
- 列表在窄屏保持表格横向滚动。
- 无数据时使用紧凑的 `Empty.PRESENTED_IMAGE_SIMPLE`，文字为“暂无商机”，说明为“客户确认明确采购需求后，可以创建商机进行持续推进。”，并提供同一主按钮。

新建使用约 600px 的嵌套 `Drawer` 和 `ProForm`。固定客户展示为当前客户且不允许修改。负责人默认当前客户负责人；联系人只加载该客户联系人，空时显示“暂无联系人”。表单分为基本信息、成交预期、需求信息、跟进计划和备注，字段为名称、客户、主要联系人、负责人、阶段、预计金额、预计成交日期、客户需求、采购范围、下一步、下次跟进时间和备注。

名称和文本输入在提交前去除首尾空格；金额限制为非负安全整数并转换为分；提交期间按钮 loading 且不可重复提交。失败时保留表单，优先展示后端业务错误，否则显示“商机创建失败，请稍后重试”。成功时显示“商机创建成功”。

## 刷新与测试

新建成功后关闭嵌套 Drawer，依次触发商机 `ProTable` reload、客户详情 reload 以及动态 reload，并通知父级客户列表刷新。不会调用 `window.location.reload()`。

服务端测试覆盖：五阶段迁移后的默认值和校验、创建事务字段映射、首个有效商机的客户推进及双活动写入、已有有效商机/已成交客户不重复写状态活动。前端测试覆盖：工具栏和 Empty CTA 共用创建入口、表单默认值和校验、成功后的局部刷新、错误时表单保留。

## 非目标与后续

- 商机详情 Drawer 当前只保留统一 handler，后续独立实现。
- “更多”菜单暂保留查看入口；编辑、标记成交、标记失败和删除将在详情/操作流程成熟后接入。
- 报价单的 `opportunityId` 关联作为下一阶段的报价领域改造，不在本次迁移中修改。
