# 线索运营闭环设计

## 目标

把现有“线索录入与列表”升级为可被销售团队日常使用的最小闭环：线索有明确归属或进入公海，人员只能处理自己有权限的线索，每次跟进可追溯，合格线索可安全转为客户与联系人。

## 边界

本期不实现商机、合同、订单、营销自动化、评分或报表。线索不会直接复用客户活动记录；线索活动独立保存。客户、联系人、公海和数据范围继续以现有 CRM 规则为准。

## 归属与可见性

- 线索的唯一负责人是 `ownerUserId`，同时保存 `ownerDepartmentId` 用于部门范围。
- 新增线索允许选择所属人；未选择时进入线索公海（`ownerUserId = null`）。
- 管理员可分配和转交；销售主管可处理本部门范围；普通销售只能查看和处理本人线索，以及按权限领取公海线索。
- 后端在所有列表、详情和写操作计算数据范围，前端筛选不能代替授权。
- 列表与详情返回负责人姓名，列表默认展示“所属人”和“下次跟进时间”。

## 生命周期与跟进

状态只描述线索的业务事实和资源投入结论，不是可任意编辑的标签；负责人、公海归属和跟进是否逾期均为独立维度，不能改变线索状态。

状态为：待处理、跟进中、有效、已转化、无效。

- 新建、导入或进入公海的线索默认是待处理，表示尚未产生处理结论。
- 首次保存一条真实的处理/跟进记录时，待处理自动进入跟进中；不提供额外的“改为跟进中”按钮。
- 跟进中表示正在验证对象和机会。跟进记录保存时间、方式、内容、处理结果/事实、下次跟进时间和操作人；活动写入和最近/下次跟进时间回写必须在同一事务中完成。
- 判为有效不是主观的“感觉有希望”：至少应能识别联系人或主体，存在回访路径，并记录需求/适配证据和明确的下一步。预算、决策链和采购时间可逐步补充，不作为一律阻断条件。
- 只有有效线索可转化。转化表示客户和联系人已成功关联或创建，不表示成交；成交属于后续商机或订单流程。
- 作废必须选择/填写原因（如重复、非目标、无需求、无法联系、联系方式错误、明确拒绝等）。无效和已转化是日常处理终态，普通编辑和跟进均不可执行。
- 对错误作废或新的外部信号，后续可提供受权限控制的“重新激活”动作，必须记录原因和操作者；不得通过普通编辑接口直接改状态。

每条跟进保存跟进时间、方式、内容、下次跟进时间和操作人；写入活动与回写线索的最近/下次跟进时间必须在同一事务中完成。作废必须填写原因。

## 转为客户

不提供无确认的“直接一键转化”。在线索为有效状态时提供“转为客户”，由服务端返回重复候选。用户在弹窗中选择关联已有客户，或确认新建客户；联系人可选择已有联系人或创建。服务端在单一事务中再次查重、创建或关联客户/联系人、写入来源与负责人、标记线索为已转化并保存引用。

转化失败时不应留下半成品客户或联系人；重复提交和并发转化只能成功一次。转化后线索和跟进历史保留，可跳转关联的客户与联系人。

服务端按以下顺序执行：校验线索仍为有效 → 查询并展示重复候选 → 接收关联/创建选择 → 在事务内再次查重 → 创建或关联客户和联系人 → 回写线索的关联引用、转化时间和已转化状态。任一步失败均整体回滚，线索保留为有效。

## 页面与文案

线索列表提供：全部、我的线索、待跟进、公海、已转化、无效等系统视图。默认表格字段为联系人、公司名称、手机号、状态、所属人、下次跟进时间、创建时间、操作。操作按状态与权限显示：

- 待处理：查看、领取/分配/转交、跟进、作废；
- 跟进中：查看、跟进、领取/分配/转交、判为有效、作废；
- 有效：查看、跟进、领取/分配/转交、转为客户、作废（按权限）；
- 无效：查看作废原因；仅具备权限者可重新激活；
- 已转化：查看转化信息并跳转关联客户/联系人。

“领取、分配、转交、退回公海”只改变归属；即使有效线索退回公海或被新销售领取，也仍保持有效。逾期由下次跟进时间计算，仅用于待办、提醒和统计。

“新增线索”表单使用联系人、公司名称、手机号、邮箱、线索来源、意向说明、所属人；未选择所属人时明确提示“将进入线索公海”。所有文案遵循已确认的中文 SaaS 文案规范。

## API 与权限

补充详情、编辑、领取、分配、判为有效、作废、跟进记录、转为客户及（后续）重新激活 API。状态不能出现在通用编辑 API 的可写字段中；每个业务动作单独设置 `crm:lead:*` 权限。列表、详情和写入都由服务端授权。OpenAPI 与管理端服务类型同步更新。

## 验收

1. 新增线索可以指定所属人或进入公海，列表显示负责人姓名。
2. 不同角色无法绕过 API 读取或操作越权线索。
3. 跟进记录可追溯，并正确更新下一次跟进时间。
4. 有效线索可在查重确认后转为客户，转化结果可回溯且不会重复创建。
5. 线索列表和详情仅展示当前状态可执行的操作。
6. 负责人、公海与逾期变化不会改写线索状态；所有状态变化均可在活动记录中追溯。
