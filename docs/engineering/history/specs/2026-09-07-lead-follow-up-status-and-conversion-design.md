# 线索跟进状态与客户转换设计

## 目标

将 `/crm/leads` 从固定生命周期改为用户在每次跟进时明确选择状态的工作方式；客户转换独立于跟进状态，任意线索均可转换，转换完成后提供“查看客户详情”入口。

## 问题与决策

当前实现把 `new → processing → qualified → converted` 当作互斥生命周期。首条跟进会自动推进状态，判为有效是转客户的前置条件，作废/激活通过独立弹窗完成。这会把销售的实际判断拆散，并把“客户是否已经关联”错误地作为线索状态。

本设计将三个概念分离：

1. **跟进状态**是销售对线索当前判断，值固定为 `未处理`、`联系方式有效`、`联系方式无效`、`关闭`，由用户在写跟进时选择。
2. **跟进活动**是按发生时间保存的沟通与审计记录，页面按最新到最早展示。
3. **客户转换**是客户/联系人关联动作，不改变跟进状态；它只在转换成功后记录关联 ID 和转换时间。

## 数据语义

### 线索

将现有 `crm_lead.status` 收敛为下列四个持久化值：

| 存储值 | 展示文案 | 含义 |
| --- | --- | --- |
| `pending` | 未处理 | 尚未判断，或仍在等待有效联系/信息 |
| `contact_valid` | 联系方式有效 | 已确认可联系，可继续推进 |
| `contact_invalid` | 联系方式无效 | 已确认联系方式或目标不成立 |
| `closed` | 关闭 | 本轮不再推进 |

新建线索初始为 `pending`。跟进状态不因写入第一条活动自动改变；每次跟进请求必须提交选定的状态。`closed` 和 `contact_invalid` 不锁定资料编辑、写跟进或客户转换；后续跟进可显式改回任意其他状态。

保留 `convertedCustomerId`、`convertedContactId` 与 `convertedAt`。它们组成独立的“是否已转客户”关系；不再使用 `converted` 作为 `status`。已经关联客户的线索仍保留最后一次跟进状态与完整时间线，但不能重复转换。

现有 `qualified`、`disqualified`、`converted` 历史值的兼容规则：读取时分别映射为 `contact_valid`、`contact_invalid`、`pending`；历史 `converted` 同时视为已转客户。迁移将实际库值更新为相应的四值，确保筛选、索引和 API 枚举一致。

### 跟进活动与审计

`POST /leads/:id/activities` 增加必填 `followUpStatus`。服务在同一事务中：

1. 写入用户选择的沟通活动；
2. 更新 `lastFollowUpAt`、`nextFollowUpAt` 和 `crm_lead.status`；
3. 仅当新旧状态不同，写入一条 `status_change` 活动，内容为 `跟进状态由「<旧>」变为「<新>」`。

状态审计的 `occurredAt` 必须与该次沟通一致。时间线按 `occurredAt DESC` 排序；同一时刻时先显示用户沟通，再显示其状态审计，保证阅读因果。创建、负责人变更、客户转换也保留为系统活动。

### 客户转换

`GET /leads/:id/conversion-preview` 与 `POST /leads/:id/convert` 不再要求任一跟进状态。转换继续在事务和行锁内完成，仍要求明确的客户与联系人选择。成功时仅设置转换关联字段、写 `conversion` 审计活动并返回客户/联系人；不得覆盖 `crm_lead.status`。

## 页面交互

### 列表

状态列展示四个跟进状态；新增或保留“已转客户”独立标识/筛选，不与状态列互斥。行操作包含查看、编辑、写跟进、转为客户或查看客户详情、转移负责人；不再显示判为有效、作废、重新激活等旧生命周期命令。

### 写跟进

写跟进弹窗字段顺序为：跟进类型、实际跟进时间、跟进内容、跟进状态、下次跟进时间。`跟进状态`始终可见且必填：新线索默认 `未处理`，其他线索默认当前值但可以调整。提交成功后刷新抽屉标题、时间线和列表行；不关闭详情抽屉。

### 详情抽屉与动态

抽屉标题显示当前跟进状态；右上角始终显示“写跟进”和“转为客户”（尚未转换时）。转换成功后不自动跳转，原按钮替换为“查看客户详情”，点击后打开关联客户详情。动态默认按最新到最早显示；筛选继续按活动类别工作。

## 权限与边界

现有跟进创建权限继续保护写跟进；状态由该请求内的 `followUpStatus` 修改，不新增裸露的任意 PATCH 状态接口。转换保留现有转换权限和数据范围检查。转换已完成时拒绝第二次转换，但绝不因 `pending`、`contact_invalid` 或 `closed` 拒绝首次转换。

## 验收标准

1. 新建线索为“未处理”；首次跟进保存的状态以用户选择为准。
2. 每次状态改变只产生一条紧随该沟通的审计活动；同一时间戳下沟通显示在审计之前。
3. “联系方式无效”与“关闭”线索可以继续写跟进并改回其他状态。
4. 任意未转客户线索均可完成客户转换；转换后状态不被覆盖。
5. 转换后详情按钮显示“查看客户详情”，可打开正确的关联客户。
6. 写跟进成功后当前抽屉、动态和列表行无需手动刷新即可显示最新状态和时间。
