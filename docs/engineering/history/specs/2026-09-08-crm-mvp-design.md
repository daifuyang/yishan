# 面向小型 B2B 团队的 CRM MVP 设计

## 1. 背景与目标

本方案面向尚未使用 CRM 的小型通用 B2B 销售团队。首个 MVP 的目标不是复刻大型 CRM 的全部能力，而是让团队可以持续回答四个问题：客户是谁、谁负责、下一步做什么、离回款还有多远。

本设计定义目标产品，不以当前实现为边界。

### 1.1 成功标准

- 销售可完成从线索进入、资格判断、客户与联系人建立、商机推进、报价、签约到回款登记的闭环。
- 销售主管可在不依赖线下表格的情况下查看团队漏斗、逾期行动和待回款。
- 每个进行中的销售对象都有明确负责人和可追溯的下一步。
- 产品结构能够支持后续配置、自动化、审批和售后扩展，而无需推翻对象关系。

### 1.2 非目标

- 不在 P0 引入 AI 评分、营销自动化、复杂审批、字段级脱敏、自定义对象、复杂协同人、库存、发票或财务系统同步。
- 不将工单纳入首个销售闭环。
- 不针对特定行业预置行业字段或行业流程。

## 2. 设计原则

1. **责任先于提醒。** 下次跟进只属于有负责人的对象；无负责人公海记录使用入池时间和池内时长，而不是逾期跟进。
2. **一个事实只由一个对象表达。** 线索池和客户公海是无负责人记录的视图，不是额外状态；赢单和丢单是商机结果，不是进行中阶段。
3. **经营对象与活动分离。** 线索、客户、商机、报价、合同、回款保存业务事实；活动保存电话、会议、拜访和任务等行动轨迹。
4. **金额从明细或事实推导。** 报价总额由产品明细汇总，回款计划状态由到期日与核销金额计算，避免手工状态失真。
5. **先减少摩擦，再逐步治理。** P0 采用轻量权限、软提醒和配置化枚举；复杂审批和自动化留到后续。
6. **表格优先、详情可追溯。** 列表用于筛选、比较和处理；详情用于完成上下文中的信息阅读、活动记录和状态推进。

## 3. 对象关系与销售闭环

```text
来源枚举 → 线索 ──未分配──→ 线索池
              └─ 合格转化 → 客户 → 联系人
                                  └→ 商机 → 报价单 → 合同 → 回款
                                               ↑
                                            产品明细

线索 / 客户 / 联系人 / 商机 / 报价单 / 合同
  └→ 活动（电话、微信、邮件、会议、拜访、任务、备注）

客户 / 合同 └→ 工单（P1 售后闭环）
```

### 3.1 对象边界

| 对象 | 唯一职责 | 不承担的职责 |
| --- | --- | --- |
| 线索 | 记录尚未确认价值的潜在客户信息及资格判断 | 不作为收入预测对象 |
| 线索池 | 展示无负责人的线索并提供领取、分配 | 不单独维护生命周期状态 |
| 客户 | 沉淀已识别的合作主体与归属 | 不表达具体交易进度 |
| 联系人 | 记录客户侧人员及其决策角色 | 不替代客户或商机 |
| 商机 | 记录可预期交易、阶段、金额和预计成交时间 | 不作为合同或回款事实 |
| 产品 | 维护可销售的标准目录、单位和标准价格 | 不承担库存或成本 |
| 报价单 | 记录可版本化的商业报价与产品明细 | 不替代最终合同 |
| 合同 | 记录最终签约和履约事实 | 不替代商机阶段 |
| 回款 | 记录回款计划、实际到账及核销 | 不直接编辑应收状态 |
| 拜访 | 作为活动中的高价值类型独立查询和统计 | 不重复建设通用活动模型 |
| 工单 | 记录售后受理与处理闭环 | 不进入销售漏斗 |

### 3.2 关键关系

- 线索合格后创建或关联客户、联系人；是否同时创建商机由销售判断。
- 一个客户可关联多个联系人、商机、合同和工单。
- 一个商机可关联多个报价单；同一时刻仅一个有效报价。
- 一个合同可关联多个回款计划和实际回款记录。
- 一条活动可关联一个主业务对象，并可关联客户、联系人或商机作为上下文。

## 4. MVP 范围与状态

### 4.1 分层范围

| 业务域 | P0 | P1 及以后 |
| --- | --- | --- |
| 市场管理 | 线索、线索池、手工录入、导入、领取、分配、转化 | 评分、自动分配、自动回收、批量培育 |
| 客户管理 | 客户、客户公海、联系人、重复提示 | 客户画像、协同人、保护期、自动释放 |
| 销售管理 | 商机、产品、报价、合同、回款、拜访活动 | 预测模型、复杂定价、审批、电子签、财务同步 |
| 售后管理 | 工单对象边界与基础资料 | 完整受理、分派、处理、确认与关闭流程 |
| 工作台 | 今日待办、逾期活动、无下一步商机、待回款、我的漏斗 | 可配置报表、预测与智能建议 |

### 4.2 最小状态模型

| 对象 | P0 状态或阶段 | 规则 |
| --- | --- | --- |
| 线索 | 待处理、跟进中、已合格、已无效 | 归属与是否在池内独立；转化为可追溯事件 |
| 客户 | 正常、停用 | 公海归属独立于客户状态 |
| 商机 | 可配置阶段；默认需求确认、方案沟通、商务谈判、成交 | 进行中阶段与赢单、丢单结果分离 |
| 报价单 | 草稿、已发送、已接受、已拒绝、已作废 | 仅一个有效报价 |
| 合同 | 草稿、待签约、履约中、已完成、已作废 | 合同金额是最终约定事实 |
| 回款计划 | 待回款、部分回款、已回款、已逾期 | 由到期日和核销金额计算 |
| 工单 | 待受理、处理中、待确认、已关闭 | P1 实施，不影响销售漏斗 |

## 5. 统一页面与文档规范

### 5.1 页面模式

| 页面 | 结构 | 规则 |
| --- | --- | --- |
| 列表页 | 标题、视图或指标、搜索区、`ProTable`、分页 | 搜索只保留高频条件；列按身份、状态、负责人、下一步、金额、操作排序 |
| 详情工作区 | 顶部身份与关键动作；左侧资料与关联信息；右侧活动时间线 | 在不离开上下文的前提下阅读、记录活动和推进对象 |
| 新建/编辑 | `ModalForm` 或抽屉表单，字段分组，底部提交 | 仅收集当前动作的必要字段 |
| 设置页 | 枚举或规则列表、搜索、表格、表单 | 枚举由管理员维护，业务页只展示名称 |
| 工作台 | 今日待办、逾期、无下一步、漏斗、待回款 | 优先呈现下一项可执行动作 |

### 5.2 产品文档标准

每个模块文档均保留统一章节，并在“页面设计”中以 Markdown 表格描述：

- 页面区块与布局；
- 搜索字段、字段名、控件类型、选项及查询语义；
- 列表字段、展示类型、宽度、空值、状态与操作规则；
- 详情区块、关联信息、时间线和动作；
- 表单字段、类型、必填、校验、默认值和可见范围；
- 权限、数据范围、状态、边界、MVP 取舍和验收标准。

表格空值统一显示 `—`；状态、时间和操作列保持单行。枚举项被引用后只能停用，不直接物理删除；业务页只回显枚举名称，不展示编码或 ID。

## 6. 权限、配置与审计

| 角色 | 默认数据范围 | P0 主要能力 |
| --- | --- | --- |
| 系统管理员 | 全部数据 | 用户与角色、枚举配置、全部对象与归属调整 |
| 销售主管 | 本人及本部门 | 团队漏斗、公海分配、本部门对象处理 |
| 销售人员 | 本人负责的数据和可领取公海记录 | 日常录入、跟进、商机推进、报价、合同、回款登记 |
| 售后人员 | 已授权客户、合同与工单 | P1 的工单处理，不修改销售金额或阶段 |

- 权限按查看、创建、编辑、删除、分配、领取、转化、导出拆分。
- 每个可执行对象仅有一位主要负责人。
- 负责人、资格判断、阶段、金额、预计成交日、报价结果、合同状态、回款登记和核销必须可追溯。
- 线索来源、客户级别、行业、商机管道与阶段、丢单原因、产品分类与单位、报价状态、合同状态、回款方式、工单类型与优先级均由设置维护。
- 客户、联系人和线索创建时以公司名称、手机、电话、邮箱提供重复提示，不强制阻断。

## 7. 经营口径

| 主题 | P0 规则 |
| --- | --- |
| 下一步 | 仅针对有负责人线索、客户和进行中商机；包含类型、计划时间和说明 |
| 商机预测 | 预测金额 = 预计金额 × 阶段默认概率；销售不可逐条任意修改概率 |
| 报价金额 | 明细行金额 = 数量 × 单价 × 折扣；总额由明细自动汇总 |
| 合同金额 | 可从已接受报价带入；保存最终约定金额，后续不随报价改动 |
| 回款计划 | 计划金额合计不得超过合同金额 |
| 实际回款 | 记录到账日期、金额、方式、备注，并核销到一个或多个计划项 |
| 回款状态 | 由到期日、计划金额和核销金额计算，不可人工改写 |
| 赢单/丢单 | 赢单需关联合同或填写跳过原因；丢单必须记录原因 |

进行中商机没有下一步时显示醒目提示，但 P0 使用提醒而非强制拦截。

## 8. 研究依据与限制

本设计参考主流 CRM 的通用对象模型和工作方式，而非复制特定厂商的企业级功能：

- [Microsoft Dynamics 365：从线索到报价的商机流程](https://learn.microsoft.com/en-us/dynamics365/guidance/business-processes/prospect-to-quote-pursue-opportunities-overview)说明线索、商机、报价和订单到现金的上下游关系。
- [Salesforce：线索转化](https://help.salesforce.com/s/articleView?id=leads_convert_parent.htm&language=en_US)支持线索合格后关联或创建客户、联系人和商机的分层模型。
- [Pipedrive：活动](https://support.pipedrive.com/en/article/activities)将电话、会议、任务和邮件等行动关联至线索、联系人、组织和商机，用于明确下一步。
- [Pipedrive：商机管道优先级](https://support.pipedrive.com/en/article/how-are-deals-ordered-in-the-pipeline-view)以最近计划活动和逾期活动帮助销售确定工作优先级。
- [HubSpot：商机默认属性](https://knowledge.hubspot.com/properties/hubspots-default-deal-properties)包含阶段、进入阶段日期、负责人和活动计数等可追溯经营字段。
- [Ant Design：数据展示规范](https://ant.design/docs/spec/data-display/)支持以表格、搜索、筛选和分页呈现结构化信息，并规定空值展示和字段排列原则。

上述资料用于验证对象边界和交互方向。具体状态名称、字段集合、金额规则和 P0/P1 划分是针对小型通用 B2B 团队的产品设计判断，不代表任一厂商的默认配置。
