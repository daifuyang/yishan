# 客户公海

## 1. 产品定位

### 1.1 解决什么问题

集中管理无负责人的客户，使团队领取或分配从待处理到已合格的客户主体；公海只解决归属，不替代客户生命周期判断。

### 1.2 使用角色

销售人员领取；主管和管理员分配、回收和查看池内时效。

### 1.3 与其他模块的关系

客户公海是负责人为空的客户视图，不是客户状态；领取后返回客户列表。

## 2. 核心业务流程

创建未分配客户或退回公海 → 记录入池时间 → 领取或分配 → 客户进入负责人范围 → 在客户详情中跟进、维护生命周期并按条件创建商机。

## 3. 页面设计

### 3.1 列表页

页面使用 `PageContainer` 承载 `ProTable`，以客户 ID 为行标识。仅查询负责人为空的客户，默认按入池时间正序展示；工具栏提供刷新、密度和列设置，主操作为“领取客户”。

| 区块 | 布局 / 组件 | 展示内容或行为 |
| --- | --- | --- |
| 页面标题 | `PageContainer` | 显示“客户公海”，并展示当前筛选结果数量。 |
| 搜索区 | `ProTable` 内置搜索表单 | 默认显示关键字、级别和行业；可展开来源、入池时间。 |
| 工具栏 | 表格工具栏 | 刷新、密度和列设置；不提供新建客户入口。 |
| 数据表格 | `ProTable` | 客户名称可打开详情；支持分页和横向滚动。 |
| 分页 | 内置分页 | 支持切换每页条数和翻页。 |

搜索字段配置如下。

| 搜索标签 | 字段名 | 控件类型 | 选项 / 行为 |
| --- | --- | --- | --- |
| 关键字 | `keyword` | 文本输入框 | 匹配客户名称、手机、电话、邮箱和微信。 |
| 客户级别 | `levelId` | 下拉选择 | 读取设置中启用的客户级别。 |
| 行业 | `industryId` | 下拉选择 | 读取设置中启用的行业。 |
| 客户来源 | `sourceId` | 下拉选择 | 读取设置中启用的来源枚举。 |
| 生命周期 | `lifecycleStatus` | 枚举多选 | 待处理、跟进中、已合格、已无效；仅用于筛选，不表示是否在公海。 |
| 入池时间 | `poolEnteredAtRange` | 日期范围选择器 | 按进入公海的时间筛选。 |

表格列配置如下。

| 列标题 | 字段名 | 展示类型 | 宽度 | 展示规则 | 是否参与搜索 |
| --- | --- | --- | --- | --- | --- |
| 客户名称 | `name` | 文本链接 | 240 | 点击打开详情；空值显示 `—`。 | 是 |
| 客户级别 | `levelName` | 枚举标签 | 96 | 回显配置名称。 | 是 |
| 行业 | `industryName` | 文本 | 120 | 回显配置名称。 | 是 |
| 客户来源 | `sourceName` | 文本 | 120 | 只显示具体枚举名称。 | 是 |
| 生命周期 | `lifecycleStatus` | 生命周期标签 | 96 | 显示待处理、跟进中、已合格或已无效；与入池状态分离。 | 是 |
| 入池时间 | `poolEnteredAt` | 日期时间 | 168 | 入池时写入，不用创建时间替代。 | 是 |
| 池内时长 | `poolDuration` | 时长文本 | 104 | 由当前时间减入池时间计算；不属于客户字段。 | 否 |
| 创建时间 | `createdAt` | 日期时间 | 168 | 使用日期时间格式。 | 否 |
| 操作 | `option` | 操作链接 | 128 | 查看、领取；主管和管理员额外显示分配。 | 否 |

不展示下次跟进和逾期提醒。

### 3.2 详情页

详情使用右侧抽屉。主信息在左侧呈现，右侧保留历史活动与归属变更时间线；池内页面不提供写跟进入口。

| 区块 | 布局 / 组件 | 展示内容或行为 |
| --- | --- | --- |
| 标题区 | 抽屉标题 | 客户名称、档案状态、生命周期、入池时间、池内时长；右侧显示领取或分配。 |
| 基本资料 | 两列信息网格 | 类型、级别、行业、来源、意向说明、手机、电话、邮箱、微信、地址、官网和说明。 |
| 生命周期判断 | 只读条件区块 | 下一步、资格证据、无效原因、判断人和判断时间；池内不可变更。 |
| 关联摘要 | `Tabs` | 保留联系人、商机、报价、合同、回款五个页签，显示数量和只读摘要；池内不显示新建入口。 |
| 右侧动态 | 活动时间线 | 展示历史沟通、生命周期、归属变更和入池记录，支持类型和时间筛选。 |
| 操作区 | 按钮组 | 销售显示领取；主管与管理员显示分配；领取或分配后进入客户详情完成编辑和跟进。 |

### 3.3 新建 / 编辑

客户公海不单独提供新建表单。新建客户时未指定负责人，或已分配客户执行“退回客户公海”后，记录进入本页面；编辑复用客户资料表单。

| 字段 | 字段名 | 组件类型 | 操作 | 校验 / 展示规则 |
| --- | --- | --- | --- | --- |
| 负责人 | `ownerUserId` | 人员选择器 | 领取 / 分配 | 领取时固定为当前用户；分配时选择有客户访问权限的人员。 |
| 入池时间 | `poolEnteredAt` | 系统写入 | 退回公海 | 用户不可编辑；每次重新入池时刷新。 |
| 退回原因 | `poolReturnReason` | 多行文本框 | 退回公海 | 可选；最多 1000 字，写入归属变更记录。 |

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| 客户名称 | 文本 | 是 | 不能为空并提示重复。 |
| 类型、级别、行业、来源 | 枚举下拉 | 否 | 设置维护。 |
| 联系方式与说明 | 文本、多行文本 | 否 | 用于识别和补充背景。 |

池内需领取或分配后才可编辑、写跟进、变更生命周期或创建联系人、商机、报价、合同和回款。

## 4. 数据模型

### 4.1 核心字段

复用客户资料及 `lifecycleStatus`、意向说明、下一步、资格证据和无效原因；负责人为空并记录入池时间，池内时长由当前时间计算。

### 4.2 状态

保留客户正常、停用状态，不另设公海状态。

### 4.3 关联关系

领取或分配建立客户负责人关系；退回公海解除负责人关系并重新记录入池时间。

## 5. 功能需求

### 5.1 查询

支持关键字、级别、行业、来源和入池时间筛选，支持按池内时长排序。

### 5.2 新增

允许直接创建无负责人客户，系统记录入池时间。

### 5.3 编辑

池内不直接编辑，领取后在客户页维护。

### 5.4 状态流转

领取、分配和退回只改变归属，不改变客户档案状态或生命周期。池内客户不执行生命周期变更；领取或分配后在客户详情执行跟进和资格判断。

### 5.5 删除 / 作废

遵循客户删除和停用规则；存在经营事实的客户不能直接删除。

## 6. 权限与数据可见性

### 6.1 查看权限

具备客户查看权限的用户可查看可领取公海客户。

### 6.2 操作权限

领取、分配、退回、删除、停用、编辑、写跟进和生命周期判断分别授权；后四项在池内不提供操作入口。

### 6.3 数据范围

领取后按负责人和部门进入数据范围；池内时按公海规则开放。

## 7. 业务规则

创建时间不替代入池时间；池内时效用于运营分配，不作为销售跟进逾期。生命周期仅反映客户资格和跟进进展，不改变可领取条件；停用客户不可领取。

## 8. 异常与边界场景

并发领取只允许一人成功；停用客户不可领取；有未结经营事项的客户退回公海需主管权限；已无效客户可保留在公海供授权用户分配或重新激活，但领取不自动改变其生命周期。

## 9. MVP 范围

### 9.1 P0

查询、领取、分配、退回、入池时间、池内时长、生命周期展示与五个只读关联页签。

### 9.2 P1

保护期、自动释放、自动回收和分配策略。

### 9.3 暂不支持

池内写跟进、批量领取和智能推荐。

## 10. 验收标准

无负责人客户显示入池时间与池内时长；领取后移出公海；公海页面不显示下一步和逾期提醒。

## 11. 字段契约与交互细则

| 动作 / 字段 | 触发与前置条件 | 系统反馈与结果 | 异常恢复 / 审计 |
| --- | --- | --- | --- |
| `poolEnteredAt` | 负责人清空时系统写入 | 详情、列表显示入池时间与实时池内时长 | 用户不可编辑；再次入池刷新并记录原因。 |
| 领取 | 列表行或详情；具领取权且客户正常 | 确认后负责人设为当前用户，关闭公海详情并在客户列表打开该记录 | 并发失败提示刷新列表；记录领取人、时间。 |
| 分配 | 详情；主管或管理员具分配权 | 选择可访问人员并确认；客户移出公海 | 人员不可用时保留选择并提示重新选择；记录前后负责人。 |
| 五个 Tabs | 池内详情点击页签 | 只读显示联系人、商机、报价、合同、回款摘要及数量 | 无记录显示空态；不显示新建、编辑或写跟进入口。 |

## 12. 页面状态

公海列表默认按入池时间正序；筛选无结果提供清空筛选，不提供新建入口。停用客户的领取按钮置灰并提示“停用客户不可领取”；已无效客户可领取但领取不会改变生命周期。领取或分配成功后，当前行从列表移除并提示结果。

## 13. UX 规格

页面复用客户 `PageContainer + ProTable` 骨架，但标题区不放新增按钮，标题旁显示公海结果数。搜索首行放关键字、客户级别、行业，来源、生命周期、入池时间收纳到展开区；表格默认入池时间升序，主操作“领取”以行内 `Button type="link"` 呈现，主管/管理员在 `Dropdown` 中看到“分配”。点击名称打开 900 宽只读 `Drawer`：顶部固定名称、两个状态标签、入池时间和池内时长，右侧只放领取/分配；左侧 `span=16` 为资料、生命周期卡和五个只读 Tabs，右侧 `span=8` 为活动与归属时间线。领取使用 `Modal.confirm`，展示领取后归属与可编辑提示；分配使用 480 宽 `ModalForm`，仅含人员选择与确认。池内禁用编辑、写跟进、Tab 新建入口和生命周期动作。
