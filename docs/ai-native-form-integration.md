# 原生表单接入 AI 的约定

AI 负责识别操作、定位记录、提取字段；页面负责打开和填写原有表单。校验、权限、上传、提交和错误处理全部沿用原实现。

## 当前协议

新增和修改返回 `render.kind = "form.prefill"`，例如：

```json
{
  "kind": "form.prefill",
  "payload": {
    "target": "user.update",
    "fields": { "id": 3, "nickname": "阿伦" },
    "missing": []
  }
}
```

`fields` 是本轮明确提供的字段补丁。编辑详情由原生页面加载，不能把查询到的整条记录当作补丁回填，否则会覆盖用户尚未保存的内容。密码、头像和附件走原生控件。

删除返回 `action.confirm`，payload 为 `{ "target": "user.delete", "id": 3, "label": "周杰伦" }`。页面重新读取记录展示确认窗口；只有点击确认才调用现有删除接口。聊天里的“确定”不会替代这个点击。

## 新模块接入步骤

1. 在 `@yishan/core-system-admin/ai-prefill` 增加明确的 target、路由和可填字段白名单。业务模块增多后再把注册入口移到产品组合层，当前不建立额外表单引擎。
2. 为已有页面增加 `AiPrefillGate`，映射字段后打开原有表单；需要连续填入时通过 `registerAiPrefillHandler` 接收补丁，只处理当前操作及同一记录。不同记录先关闭或保存当前窗口。
3. AI 工具仅返回以上 JSON，定位记录和查询选项复用现有服务、权限和数据范围。不能新增一条平行的创建、修改或删除业务路径。
4. 原有提交成功或失败时，通过 `publishAiPrefillResult` 关联 requestId 通知聊天窗口。没有真实提交结果时，只展示“已填入”或“待确认”。
5. 覆盖最小回归：只改指定字段；取消删除不发请求；确认走原接口；历史、停止和失败不自动重放；切换记录不能串数据。

预填仅存于内存，刷新失效，不进入 URL 或浏览器持久存储。旧会话里的草稿卡片保留原生表单恢复兼容，新对话采用上述协议。

## 流式体验

回复正文实时渲染；模型供应方返回的 reasoning 显示在思考区域；真实工具调用显示处理中、完成或失败状态。没有 reasoning 的模型展示正文与操作进度，不生成虚假的思考文字。快捷意图同样先返回 SSE，再执行查询和准备操作。
